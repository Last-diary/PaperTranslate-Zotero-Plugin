# Reader 面板增量重构计划

## 结论

当前项目不需要全面重写，但 `chrome/content/modules/ui/readerPanel.mjs` 已经承担过多职责。应在继续增加内容过滤配置、多个翻译提供商等中型功能前，对 Reader 面板进行小步、可运行验证的增量重构。

## 当前依据

- `readerPanel.mjs` 约 2468 行，占核心 JS 代码约 56.3%。
- 文件内约有 95 个函数，面板状态对象包含约 42 个字段。
- Markdown/数学公式渲染、面板布局、PDF 兼容访问、右键菜单、块编辑、滚动定位和翻译调度集中在同一模块。
- 可见块翻译、编辑原文后重译、全文翻译重复维护 busy、遮罩、缓存、按钮和错误状态。
- PDF 相关实现散布着 `_internalReader`、`_iframeWindow`、PDF.js DOM 等私有或内部访问。
- `panelStates` 使用不可遍历的 `WeakMap`，插件关闭时无法统一释放所有已打开的面板会话。
- 当前没有自动化测试，主要依赖语法检查、打包检查和 Zotero 运行验证。

## 重构原则

1. 不改变现有用户行为，不在模块拆分时同时增加新功能。
2. 每个阶段单独提交，并在 Zotero 中完成运行验证。
3. 优先保留 Zotero 官方公开 API；私有接口集中封装并进行能力检测和安全降级。
4. 保持原文/译文切换、块级滚动同步、右键菜单、PDF 定位、宽度记忆和自动调整大小行为不变。
5. 修改 ESM 后完全退出 Zotero，并使用 `-purgecaches` 重新启动，避免旧模块缓存影响判断。

## 实施阶段

### 第一阶段：建立回归基线

- 为不依赖 Zotero DOM 的纯函数增加测试入口：
  - 内容块过滤与归一化；
  - 原文覆盖数据的读写转换；
  - Markdown/数学公式分段处理；
  - 块级滚动锚点计算；
  - 面板宽度比例计算。
- 建立 Reader 面板手动冒烟检查清单：
  - 打开和关闭面板；
  - 原文/译文切换；
  - 拖动宽度并重新打开；
  - PDF 自动调整大小；
  - PDF 缩略图和滚动保持可用；
  - 块右键菜单全部命令；
  - 原文编辑后自动重译；
  - 面板与 PDF 双向定位；
  - 插件禁用或关闭时的清理。

验收标准：

- 所有现有纯逻辑测试通过。
- Zotero 运行冒烟检查没有发现行为变化。

### 第二阶段：统一面板会话生命周期

- 新建 `ReaderPanelSession` 或等价的会话控制模块。
- 集中保存面板状态、监听器清理函数、定时器和异步任务标识。
- 提供幂等的 `dispose()`。
- 将会话注册表改为可统一清理的结构，同时避免长期持有已关闭 Reader。
- 导出 `disposeAllReaderPanels()`，由插件 `shutdown()` 调用。
- 为加载、翻译、解析和重译任务增加取消或请求代次检查，避免面板关闭后继续更新已移除的 DOM。

验收标准：

- 重复打开/关闭面板不会积累监听器或定时器。
- 插件关闭或禁用后，已打开面板和相关任务被正确清理。
- Reader 关闭后不保留对应会话。

### 第三阶段：隔离 Zotero PDF 兼容层

- 新建 `readerPdfAdapter.mjs`。
- 集中封装：
  - Reader/PDF 就绪检测；
  - `reader.zoomAuto()` 调用和降级；
  - PDF 页面跳转；
  - 当前 PDF document/view 获取；
  - PDF 右键坐标解析；
  - PDF 块定位和高亮。
- 所有 `_internalReader`、`_primaryView`、`_iframeWindow` 和 PDF.js DOM 访问只保留在兼容层。
- 每个内部能力都进行检测，并保留带版本和执行阶段的调试日志。

验收标准：

- `readerPanel.mjs` 不再直接访问 Zotero Reader 私有字段。
- 打开右侧面板不会重建 PDF iframe。
- 自动调整大小、缩略图、右键菜单和 PDF 定位均通过运行验证。

### 第四阶段：统一翻译任务控制

- 新建 `translationController.mjs`。
- 把可见块翻译、单块重译、编辑原文后重译和全文翻译统一为一个任务执行入口。
- 通过参数控制：
  - 待翻译块 ID；
  - 是否强制刷新缓存；
  - 进度文案；
  - 完成文案；
  - 失败后是否暂停自动翻译。
- 统一维护 `translationBusy`、`translatingIds`、遮罩、按钮状态、缓存刷新和后续队列。

验收标准：

- 同一块不会同时进入多个翻译任务。
- 单块、可见块、编辑后重译和全文翻译行为与重构前一致。
- 面板关闭后不会继续刷新 UI。

### 第五阶段：拆分 UI 与渲染模块

- 将职责按边界拆分：
  - `panelRenderer.mjs`：Markdown、数学公式、图片和块 HTML；
  - `panelLayout.mjs`：面板挂载、宽度、拖拽、ResizeObserver 和样式变量；
  - `blockContextMenu.mjs`：菜单渲染、打开定位和命令分发；
  - `blockEditor.mjs`：原文/译文编辑及保存；
  - `readerPanel.mjs`：仅保留会话编排和 Zotero 注册入口。
- 修正文档和文件头中已经过时的 `#split-view` 布局描述。

验收标准：

- `readerPanel.mjs` 只承担面板编排，不再包含底层渲染和 PDF.js DOM 细节。
- 各模块依赖方向单一，不形成循环依赖。
- 全部静态检查、打包检查和 Zotero 运行冒烟检查通过。

## 暂不重构的模块

以下模块当前职责相对集中，除非后续功能直接需要，否则暂不调整：

- `storage.mjs`
- `blocks.mjs`
- `importer.mjs`
- `mineru.mjs`
- `deepseek.mjs`
- `toc.mjs`

## 建议执行顺序

先完成第一、第二阶段，再继续开发内容过滤配置或多个翻译提供商。第三至第五阶段可以分别提交和验证，不应一次性完成大规模文件搬迁。
